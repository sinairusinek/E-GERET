מעבדת תיוג וסימון טקסט

מטקסט פשוט לטקסט מעוצב — עם סימנים בלבד. בעורך שמימין יושב טקסט פשוט: רצף של תווים, בלי שום עיצוב. Markdown היא מוסכמת סימון קלה: מוסיפים סימנים לטקסט, והמחשב מפרש אותם לעיצוב — שתראו מיד בצד שמאל. נסו על הטקסט: # בתחילת שורה = כותרת · **מילה** = הדגשה · *מילה* = הטיה · - בתחילת שורה = פריט רשימה · > = ציטוט · --- בשורה משלה = קו מפריד · [טקסט](כתובת) = קישור.
שימו לב — תופעה של כתיבה דו־כיוונית: במקלדת עברית תווי הסוגריים מתהפכים, וסימנים כמו > מוצגים במראָה. המעבדה סלחנית לזה; כלים אחרים בעולם — לא תמיד.

התוצאה המעוצבת
ניסוי: אותו קובץ, שלושה מפרשים.
  1. הורידו את העבודה שלכם כ־.md והעלו את הקובץ ל־Google Drive.
  2. לחצו עליו לחיצה כפולה — תצוגה מקדימה: מה רואים? טקסט פשוט, הסימנים גלויים. Drive מציג, לא מפרש.
  3. עכשיו קליק ימני ← פתיחה באמצעות ← Google Docs: הסימנים הפכו לעיצוב! אבל בדקו את הכיוון והיישור — Docs רק מנחש שהטקסט עברי, כי ל־Markdown אין דרך להגיד "אני ימין־לשמאל". (תיקון ידני ב־Docs: File ← Language ← עברית, לסמן הכול ולהפוך כיוון פסקה.)
  4. הורידו מכאן גם את גרסת ה־.html, העלו ופתחו גם אותה עם Docs — הפעם הכיוון נכון מעצמו. למה? חזרו לתצוגה המקדימה של Drive, שמציגה את הקובץ כטקסט פשוט, ומצאו את התשובה: dir="rtl". זו בדיוק היכולת ש־HTML מוסיף על Markdown — לא רק לעצב, אלא להצהיר.
מסימנים לתגיות. את ה־Markdown מהתרגיל הקודם המחשב מתרגם ל־HTML — שפת הסימון של כל דף אינטרנט. כאן הסימון גלוי: כל קטע עטוף בתגית שנפתחת (<h1>) ונסגרת (</h1>), והדפדפן מפרש אותה לעיצוב. ערכו את הקוד שמימין — בהקלדה חופשית, או בסימון קטע ובחירת תגית מהרשימה — וראו את התוצאה משמאל.
הקוד — HTML
כך מציג זאת הדפדפן

שימו לב: התגיות, התכונות והערכים — תמיד באנגלית (<h1>, dir="rtl"); התוכן שביניהן — בכל שפה. נסו למחוק תגית סוגרת וראו מה קורה לתצוגה.

הלבוש הנוכחי: ספר
אותו סימון — לבוש אחר. לחצו על ״החלפת לבוש״ והתבוננו היטב: הקוד שמימין לא השתנה באות אחת — ובכל זאת הטקסט שמשמאל מחליף את פניו. זו חלוקת העבודה שביסוד הרשת כולה: הסימון (HTML) אומר מה יש כאן — כותרת, ציטוט, הדגשה; העיצוב (CSS, ״גיליון הסגנון״) קובע איך זה ייראה. אותה כותרת בדיוק יכולה ללבוש צורת ספר, עיתון או מכונת כתיבה — והסימון נשאר אחד. מי שמסמן היטב את המבנה, מקבל את כל הלבושים בחינם.
מסימון מעצב לסימון מתאר. קובצי ה־HTML של פרויקט בן־יהודה אומרים לדפדפן איך להציג: <strong> = הדגש, <h2> = כותרת גדולה. XML מתאר מה הדבר הוא: <emph> = מילה מוטעמת, <div type="section"> = יחידת טקסט מסוג מסוים, <note> = הערת שוליים. נמיר קובץ אמיתי, נראה בדיוק אילו החלטות ההמרה קיבלה — ואז תמציאו תגיות משלכם ותסמנו כל מה שנראה לכם ראוי לסימון: אנשים, מקומות, תאריכים, רגשות, טענות. אין רשימה נכונה — השם בידיכם.
רגע של דקדוק: תגית, תכונה, ערך
<book genre="play" lang="he">בחוץ</book>
  • תגית (tag) — אומרת מה הדבר: book. נפתחת ונסגרת, והסוגרת מקבלת לוכסן.
  • תכונה (attribute) — פרט נוסף על הדבר: genre, lang. יושבת תמיד בתוך התגית הפותחת, ואפשר לצרף כמה שרוצים.
  • ערך (value) — התשובה של התכונה, תמיד בין מרכאות: "play".
  • תוכן — הטקסט עצמו, בין הפותחת לסוגרת: בחוץ. שימו לב לחלוקה: תגיות, תכונות וערכים — באנגלית; התוכן — בשפת המסמך.

בשביל מה תכונות? כדי לדייק בלי להמציא תגית חדשה לכל מקרה: <date calendar="hebrew">ט״ו בשבט תרס״ד</date> לעומת <date calendar="gregorian">1904</date> — אותה תגית, הבחנה אחרת. שימו לב אליהן בהמרה שתיכף נריץ: type="section" היא בדיוק כזאת.

4אוספים ומשווים — האם כולנו תייגנו אותו דבר?

      

        כל אחד ואחת הורידו קובץ XML עם התגיות שהמציאו. שלחו את הקבצים למנחה (מייל, WhatsApp, AirDrop —
        כל דרך טובה), והמנחה יעלה כאן את כולם בבת אחת. הטבלה שתתקבל מראה מי המציא אילו תגיות —
        וכמה שמות שונים נולדו בחדר אחד לאותו רעיון בדיוק. זו בדיוק הבעיה שלשמה הומצא תקן משותף.

        בשלב ההשוואה ראינו: חדר אחד, טקסט אחד — ועשרות שמות תגיות שונים לאותם רעיונות.

        <persName> — ההבדל היחיד הוא ההסכמה.
        כאן נקודד מסמך שלם לפי התקן, בליווי צמוד: המדריך בצ׳אט יוביל אתכם בשלושה שלבים —
        מילוי תעודת הזהות (teiHeader), בניית המבנה, ותיוג לפי הפרק הרלוונטי בתקן:
        התכתבות או דרמה.
